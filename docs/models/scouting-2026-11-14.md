## 3. Evidence on small models for GEC / Spanish

- [arXiv 2505.06004](https://arxiv.org/html/2505.06004v1) — 17 models ≤ 9B, GEC in EN/DE/IT/SV (no Spanish): Gemma-2 9B 1st, Qwen2.5 7B and Aya 2nd–3rd, **Gemma-2 2B 4th and close**; Phi-3 weak; SmolLM last. The longest, most specific prompt won 32 of 36 settings.
- [arXiv 2609.10810](https://arxiv.org/pdf/2609.10810) — minimal-edit GEC (English): plain zero-shot prompts over-correct (precision < 45); a **minimal-edit instruction + a few examples** gives the biggest gain; Qwen3-8B F0.5 68.8 vs Gemini 3 Flash 73.7.
- [La Leaderboard](https://arxiv.org/html/2507.00999v1) (Spanish, < 10B): gemma-2-9b-it 61.7, Llama-3.1-8B 59.0, Qwen2.5-7B 58.8, aya-expanse-8b 55.4, gemma-2-2b-it 54.9, Salamandra-7B 52.2.
- [arXiv 2601.03874](https://arxiv.org/html/2601.03874v1): ≤ 2B models are about 3× worse than GPT-3.5 at GEC.
- No Spanish GEC numbers found yet for Gemma 4, Qwen 3.5, Ministral 3 or Granite 4.1 → our harness is the measurement.

**Takeaway:** expect the local models to stay well below flash-lite on detection. The realistic use is a hybrid (§4): a small local model for dialogue, the best available model for corrections. Our prompt is already long and specific; the next cheap lever is few-shot examples (2–3 corrections in the system prompt). That changes the prompt, so it must be measured on a held-out set (5.7: `eval/cases/heldout/`, not created yet) to avoid teaching to the test.

## 4. Hybrid pipelines to evaluate next (designs, not built)

1. **Local LanguageTool pre-check → LLM.** LanguageTool (LGPL 2.1+, Java 8+ HTTP server or Docker `erikvl87/languagetool`, ~256–512 MB RAM; download ≈ 250 MB, unverified) catches spelling/accents/some agreement offline and costs no quota. The LLM gets its hits as hints. Needs Java or Docker on Roman's laptop → Roman's decision (new local dependency).
2. **Split by situation:** a fast local 3–4B model (`gemma4:e2b` / `ministral-3:3b`) writes the reply; flash-lite (or the best local) does the correction JSON. Two calls per turn, but quota per turn drops if the dialogue call is local.
3. **Offline analysis:** `gemma4:e4b-it-qat` over the error log (1.6) at night — latency doesn't matter.

Harness support for (1) and (2) is a separate PR (an eval "pipeline" provider).

## 5. Code change in this PR (Ollama provider)

- **`think: false` for thinking models.** Qwen 3/3.5 (and deepseek-r1, magistral) think by default, which multiplies CPU latency and is useless for a one-line reply. `OLLAMA_THINK=auto` (default) sends `think: false` only for those families; `false` / `true` force it for any model. Other models get no `think` field (older Ollama versions reject it for non-thinking models).
- **Exact tag match.** `_ping` compared only the family (`gemma4`), so with `gemma4:e4b-it-qat` installed, `gemma4:e2b` looked available and every case would fail with 404. Now the tag must match (with implicit `:latest`).
